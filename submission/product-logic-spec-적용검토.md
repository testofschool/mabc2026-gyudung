# product-logic-spec 적용 검토 — 규정다름 MABC 2026 결선

## 서비스 로직 개요

규정다름의 핵심 로직은 admrul-diff 스크립트에 있다. 제품 로직 스펙 관점에서 정리하면:

### 상태
- 초기 상태: 빈 입력 폼
- 로딩 상태: 대조 실행 중
- 결과 상태: diff 표 + D-day 표시
- 오류 상태: 유효성 검증 실패 / 서버 오류

### 이벤트
- "대조 실행" 클릭 → POST /api/admrul-diff
- 파일 첨부 → 폼 데이터에 파일 포함
- 샘플 불러오기 → 샘플 텍스트 로드
- 지우기 → 모든 입력/결과 초기화

### 의사결정 케이스
- 구판/신판 모두 비어있음 → 오류: "모두 입력해주세요"
- 조문 패턴(제N조) 없음 → 오류: "행정규칙 형식이 아님"
- 서버 오류 → 오류 메시지 표시
- diff 결과 없음 → "변경된 조문 없음" 표시
- 시행일 미검출 → "시행일 미검출" 표시

### 불변식
- diff 계산은 항상 스크립트(admrl_diff.py)로 수행
- LLM이 임의 추정하지 않음
- 시행일/D-day는 스크립트가 산출

### 비동기/에러 처리
- fetch 오류 → "요청 중 오류 발생" 표시
- 서버 400/500 → JSON error 필드 파싱하여 표시
- 타임아웃: 별도 처리 없음 (Vercel 서버리스 의존)

## 스크립트에 위임하는 계산
- 조문 파싱 (parse_articles)
- 시행일 파싱 (parse_enactment_date)
- Diff 판정 (added/modified/deleted)
- D-day 산출

이 계산이 제품 로직의 핵심이며, LLM이 개입하지 않는다.
