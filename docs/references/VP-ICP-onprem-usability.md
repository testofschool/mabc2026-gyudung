# VP·ICP·온프레미스·인터페이스·보상 구간 — 규정다름 (강정민, MABC 2026 결선)

최종 갱신: 2026-09-16 (제출 직전)

## 1. ICP (실무자 단위)

이 서비스의 1차 ICP는 추상적 "공무원 전체"가 아니라, 규정 개정 통지서를 실제로 받아 두 문서를 비교해야 하는 실무자 단위다.

예시(포스터에 이미 반영):
- 금융위원회 보험과
- 개인정보보호위원회 개인정보보호정책과
- 조달청 규제개혁법무담당관

근거: 행정규칙/지침/훈령/예규/요령은 소관 부서별로 제·개정이 반복되고, 담당자가 구판·신판을 대조해야 하는 상황이 반복된다. 이때 국가법령정보센터를 경유하는 방식은 메뉴 탐색·별도 페이지 이동이 필요해 "통지서를 받은 즉시 빠르게 확인"하기에는 마찰이 있다. 규정다름은 이 지점을 노린다.

## 2. VP (가치 제안)

**핵심 VP 문장:**
> "공무원이 규정 개정 통지서를 받았을 때, 두 문서를 출력해 눈으로 비교하던 작업을 텍스트 붙여넣기만으로 수초 내에 조문 대조 + 시행 D-day까지 파악할 수 있다."

이 VP는 "규제 정보를 알기 쉽게"가 아니라 "이미 하고 있던 수작업을 더 빠르게"라는 지점에anchored되어 있어, 과한 미래조망보다 실제 사용에 가깝다.

보조 VP(라벨별):
- 속도: 텍스트 붙여넣기 즉시 결과. law.go.kr 동일 작업 대비 메뉴 탐색·페이지 이동 없음.
- 완전성: 조문 대조 + 시행 D-day를 한 화면에서 동시에.
- 접근성: 로그인·회원가입·API 키 없이 누구나.
- 신뢰성: LLM이 아닌 스크립트가 계산 → 재현 가능.
- 폐쇄망 대응: 핵심 계산은 Python stdlib 기반 스크립트이므로 내부망·폐쇄망 환경에서도 구판·신판 텍스트만 있으면 같은 방식으로 대조 가능.

## 3. 근거의 강도

- law.go.kr에 "비교" 관련 버튼이 존재함을 확인(lawComparePop, 행정규칙 신구조문 저장 layer 언급). 즉 "법령 비교 기능 자체가 없다"는 주장은 틀린 표현이고, "텍스트 붙여넣기 즉시 + 조문 단위 대조 + D-day 한 화면"이 없다는 표현이 옳다.
- diff 판정·시행일/D-day 계산은 스크립트(admrul_diff.py)로만 수행. LLM 임의 추정 없음. 이 점은 PRD·발표자료·포스터·400자 설명에서 일관되게 서술.

주의: "행정규칙 전용 즉시 대조 기능이 국가망에 전혀 없다"처럼 읽힐 수 있는 표현은 피했고, 실제 확인된 범위로 한정했다.

## 4. 폐쇄망/온프레미스 표현

제출용 표현(PRD·발표자료에 반영):
- "핵심 계산은 Python stdlib 기반 스크립트이므로, 내부망·폐쇄망 환경에서도 구판·신판 텍스트만 있으면 같은 방식으로 대조 가능"

이 표현은 현재 Vercel 온라인 서비스가 폐쇄망 안에 있다는 뜻이 아니라, **계산 로직을 로컬 환경에서도 같은 방식으로 돌릴 수 있다**는 의미로 범위를 정확히 한정한 것이다. 이 범위를 벗어나 "이미 폐쇄망에서 서비스된다"고 말하면 사실과 달라진다.

강화 포인트(선택):
- 포스터에도 이 한 줄을 넣으면 폐쇄망 강점이 더 분명해진다( space 허용 시).
- 데모 영상에서 "인터넷 연결 없는 환경에서도 스크립트만으로 대조 가능" 뉘앙스를 자막/구두로 보강 가능.

## 5. 인터페이스 판단 (파일 첨부 vs 붙여넣기)

- MVP(현재): 텍스트 붙여넣기.
  - 장점: 즉시성, 입력 방식이 단순, 스크립트가 텍스트를 직접 처리, 구현 리스크 낮음.
  - 단점: 긴 문서를 매번 붙여넣어야 하는 불편은 있음.
- 파일 첨부(업로드) 방식:
  - 사용자 요구("파일을 첨부해서 바로 사용할 수 있는 상태")에 더 가까울 수 있음.
  - 그러나 MVP 범위를 벗어나고, 파일 파싱·용량·포맷 처리 리스크가 증가함.
- 판단: 제출용 MVP는 붙여넣기 유지 + "파일 업로드 지원 검토"를 향후 발전 방향으로 명시하는 전략이 안전. 심사에서도 "즉시 사용 가능한 MVP"와 "향후 확장"을 구분해 읽을 수 있다.

## 6. 한국 공무원 니즈 반영 포인트

- 행정규칙/지침/훈령/예규/요령은 형식이 다양하고 조문 번호 체계도 조금씩 다르다. 규정다름은 이런 문서를 "붙여넣기" 기반으로 처리하므로, 별도 시스템 연동 없이 바로 쓸 수 있다는 점이 실무 니즈와 맞는다.
- 시행일/D-day 정보는 개정 통지 후 "지금 시행 중인지, 언제부터 시행되는지"를 바로 알아야 하는 실무 상황과 연결된다.
- "계산은 스크립트가 한다(LLM 임의 추정 없음)"는 점은 행정文书处理에서 재현성·책임 소재 측면에서 설득력이 있다.

## 7. Reward beat 관점 (발표·데모 흐름)

- 문제 인식(01): "아직도 수작업" 문장을 hook으로 사용. 청중이 "맞아, 그거 불편했지"에 걸리는 지점.
- 해결책(02): 붙여넣기만 하면 대조표 + D-day 즉시 출력 — 여기서 첫 payoff.
- 사용 흐름(03): 3단계로 끝나며 복잡하지 않다는 인상.
- 기술 구조(04): 가볍게 이해되는 아키텍처.
- 경쟁 비교(05): "우리가 왜 지금 필요한가"를 법.net/오픈API와 대비해 설명. 과주장 없이 범위 한정.
- 데모(06): 실제 동작으로 입증. 핵심 payoff는 "시행중 D-day"가 화면에 뜨는 순간.
- 향후 발전 방향(07): 파일 업로드·API 연동 등 확장은 미래 과제로 배치.

데모 영상도 동일 흐름으로 구성하면 된다(서비스 시크릿 창 접속 → 샘플 불러오기 → 대조 실행 → 대조표 + 시행중 D-day 확인 → (옵션) JSON 보기).

## 8. 제출용 한 줄 요약 (심사위원용 이미지)

"행정규칙 개정 통지서를 받은 실무자가 두 문서를 출력해 눈으로 비교하던 작업을, 텍스트 붙여넣기만으로 수초 내에 조문 대조 + 시행 D-day까지 파악하는 도구. 계산은 스크립트가 수행해 재현 가능하며, 내부망·폐쇄망 환경에서도 같은 방식으로 쓸 수 있다."
