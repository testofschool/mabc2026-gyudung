### 1-3. P0 기능 (데모 필수)

4. 로그인 없이 즉시 사용 — 구현됨, 시크릿 창에서 확인

## 2. 비어 있거나 약할 수 있는 셀 (리스크)

### 2-1. 실증 증거 부족 (가장 큰 갭)

| 영역 | 현재 상태 | 리스크 |
|---|---|---|
| VP 타당성 | 주장(논리적으로 타당) | "실제 사용자가 이 불편을 겪는다"는 증거 없음 |
| ICP 타당성 | 주장(부서는 plausible) | 실제 사용자 조사/데이터 없음 |
| 시간 절약 주장 | PRD에 "30초 vs 2~3분" 언급 | 실측 아닌 추정, 근거 약함 |
| 법.net 대비 우위의 중요도 | 차이점 설명은 있음 | "그 차이가 사용자에게 중요한가"는 입증 약함 |

**이 갭이 평가 rubric에서 "문제 정의의 근거", "타겟 사용자 검증", "해결책 타당성" 항목을 낮출 수 있음.**

### 2-2. 데모 영상 (필수, 현재 미완료)

- 제출 양식 2: 데모 영상은 필수, "현장 네트워크 장애 대비 백업으로도 사용" 명시
- 현재 미완료 → 마감(23:59)까지 사용자가 직접 촬영해야 함
- **데모 영상 품질이 심사자가 서비스를 실제로 체감하는 주요 채널**
- 여기서 VP/ICP/차별화가 실제로 보여져야 함

### 2-3. 데모 시나리오의 공무원 맥락 적합성

현재 데모 시나리오:
- A시청 자치행정과 주무관 B가 소관 지침 개정 통지 받음
- 구판·신판 텍스트 이메일로 수신
- 규정다름 접속 → 붙여넣기 → 대조 실행 → 대조표+D-day 확인
- 샘플: 시립도서관 자료실 운영 지침 (구판 2026.3.1. / 신판 2026.9.15.)

**평가:**
- 공무원 사용 맥락을 구체적 상황으로 잡은 건 좋음
- 샘플이 실제 행정규칙 형식(지침, 부칙 포함)이라 현실적
- **단, "왜 이 부서/이 지침인가"에 대한 맥락은 약함** (샘플이 가상 지침이라, 실제 특정 기관의 실제 규정이라는 증거는 없음 — 데모용이므로 정상)

**개선 여지:**
- 데모 영상에서 "실제 행정규칙 문서를 붙여넣는 장면"이 들어가면 맥락이 더 살아날 수 있음
- 서비스에 실제 행정규칙 예시(law.go.kr에서 가져온 실제 지침 텍스트)를 샘플로 넣으면 신뢰도↑

### 2-4. "왜 ICP가 이용해야만 하는가" — 필연성 약함

- VP는 "더 빠르고 편리하다"까지 설명
- "이용해야만 하는" 필연성까지는 아님 (수작업도 가능하고, 법.net 비교 기능도 있음)
- 정직한 framing: "반드시 써야 하는 건 아니지만, 현재 수작업 방식의 시간/실수 위험을 줄이는 도구"
- 이걸 "강력한 필수성"으로 포장하면 과주장, "있으면 좋은 도구"로 약화하면 경쟁력↓. 균형이 필요.

### 2-5. 폐쇄망 주장의 해석 여지

- 현재 표현은 기술적으로 참이지만, "우리 서비스를 폐쇄망에서 바로 쓴다"로 오해될 여지 있음
- 심사에서 "폐쇄망 대응"이 강점처럼 보이는데, 실제 서비스는 클라우드 → 이 갭이 지적될 수 있음
- 더 정밀한 표현 권장(위 1-6 참고)

### 2-6. method-frontier-recon 관점 — 다른 팀과의 차별화

- 다른 팀 제출물을 우리가 모름 → 직접 비교 불가
- 우리 접근(스크립트 기반, 특정 틈새, 정직한 한계 명시)은 시간적 제약 내 합리적 선택
- **위험:** 다른 팀이 "법.net 연동 + 더 풍부한 기능"으로 왔다면 우리가 뒤질 수 있음
- 우린 "즉시성 + D-day + 로그인 없음 + 스크립트 투명성"으로 차별화 중
- **이 차별화가 실제 데모에서 체감되는가**가 중요

### 2-7. 시크릿 창 첫 방문 "안내" 검증 문서 부재

- skill-to-service 성공 기준: "저장값 없는 첫 방문에서 안내가 스스로 나오고 최소 기능이 도는가"
- 현재: 정황 증거(로그인 필요 없음, 버튼 존재 등)는 있으나, **명시적 검증 리포트 없음**
- 이건 "실증" 측면에서 약한 셀

## 5. 결론 (추론)

- **기술적 완성도는 높음.** P0 기능, 성공 기준 대부분 충족, 과주장 정제됨.

- **현재 가장 큰 리스크는 데모 영상 미완료.** 이게 마감 전 필수 항목이고, 심사자가 서비스를 체감하는 주요 채널.
- **평가 rubric을 모르는 상태이므로 "만점 가능 여부"는 단정할 수 없음.** 대신 위 빈 셀 목록이 "깎일 수 있는 지점"이다.
